# 推論服務 1.1：負載控制與效能驗證強化

本次檢查服務的模型鎖等待、並發容量、例外後的資源釋放與量測程式的回應核對，補上模型准入上限與等待期限，並將回應格式、模型身分及訓練截止時間納入效能驗證，服務版本更新為 1.1.0。

## 1. 檢查發現與修正

| 檢查項目 | 發現的問題 | 本次修正 |
|---|---|---|
| 模型容量 | 模型鎖的等待請求缺少准入數量限制 | 以有界 semaphore 控制正在執行與等待的模型請求數 |
| 鎖等待 | 取得模型鎖使用無期限等待 | 設定等待期限，逾時回傳 HTTP 503 |
| 容量釋放 | 新增負載限制後需要驗證例外路徑 | 在 `finally` 釋放已取得的鎖與准入名額，測試逾時及模型例外後的恢復 |
| 分數格式 | NumPy 的維度廣播會讓陣列型分數通過特定數值核對 | 使用嚴格回應模型，並要求分數陣列維度一致 |
| 回應資料 | 量測程式未核對完整格式與訓練截止時間 | 核對必填欄位、欄位型別、截止時間與 HTTP 200，拒絕額外欄位 |

檢查過程重現了陣列型分數與錯誤截止時間被原量測程式接受的情況，本次將這些輸入加入拒絕測試，涵蓋格式、內容與身分錯誤。

## 2. 模型請求的負載控制

模型保持單一推論席位，預設准入上限為 32 筆，計數範圍包含正在執行與等待模型鎖的請求，因此最多有 1 筆執行及 31 筆等待，同步端點的執行緒池設定為 40 個名額。

請求通過格式驗證後會嘗試取得准入名額，容量已滿時回傳 HTTP 429，取得名額後會等待模型鎖，等待超過設定時間時回傳 HTTP 503，兩種回應都包含 `Retry-After: 1`。

等待期限從嘗試取得模型鎖開始計算，取得鎖後執行模型推薦，模型流程結束或發生例外時釋放鎖與准入名額，預設鎖等待期限為 1 秒。

| 設定 | 預設值 | 接受範圍 |
|---|---:|---|
| `--max-inflight` | 32 | 1 至 32 的整數 |
| `--queue-timeout` | 1.0 秒 | 正的有限數值 |
| `--torch-threads` | 1 | 正整數 |
| 模型推論席位 | 1 | 服務固定設定 |
| 同步端點執行緒池 | 40 | 服務固定設定 |

`GET /ready` 增加 `max_inflight`、`queue_timeout_seconds` 與 `threadpool_tokens`，可讀取正在運行的容量與等待設定。

## 3. 回應與量測驗證

API 與負載產生器共用嚴格回應模型，使用者 ID、模型名稱、checkpoint 雜湊、訓練截止時間及推薦清單都需要符合欄位定義，內容 ID、標題與主題為字串，分數為有限數值。

每筆成功量測需要取得 HTTP 200，再依序完成回應格式檢查、身分與截止時間核對、內容 ID 與順序核對、分數維度與數值核對，全部通過後列為成功請求。

回歸測試會拒絕陣列、字串與布林型分數，並涵蓋缺少標題、額外欄位、錯誤截止時間、使用者、模型、checkpoint、內容順序、分數、內容數量與非預期成功狀態，格式錯誤與 HTTP 錯誤都列入量測錯誤數。

## 4. 回歸測試結果

本次完整測試通過 95 項，新增 27 個案例，模型產出的八個檔案雜湊，以及 80 位使用者的 checkpoint 推薦結果也通過驗證。

| 測試範圍 | 驗證內容 |
|---|---|
| 容量已滿 | 持有模型席位時送入第二筆請求，確認回傳 429 與重試提示 |
| 等待逾時 | 保留准入名額並持有模型鎖，確認等待請求回傳 503 |
| 健康檢查 | 模型忙碌時，`/health` 與 `/ready` 仍回傳成功 |
| 恢復處理 | 容量拒絕、等待逾時與模型例外後，後續請求能取得名額並完成推薦 |
| 設定驗證 | 拒絕容量範圍外的值，以及零、負值、NaN、無限值與布林型等待期限 |
| 回應核對 | 驗證完整有效回應，並拒絕 13 種格式、身分與推薦結果錯誤 |
| 統計核對 | 成功數、錯誤數、錯誤率及每秒成功請求量依實際請求結果計算 |

## 5. 重新量測的 HTTP 效能

本次使用 Apple M5 Pro、24.0 GiB 記憶體與 Python 3.9.6，PyTorch 2.6.0、FastAPI 0.115.12 與 Uvicorn 0.34.2，客戶端與服務位於同一台電腦，經 loopback HTTP/1.1 傳輸並保留連線。

每組並發設定執行 3 回合，每回合 500 筆量測請求，每個並發工作在回合開始前先送出 5 筆暖機請求，兩個模型輪流使用 80 位既有使用者與 1 位新使用者，推薦數量為 10，啟用已讀排除。

## 6. 安裝與執行

安裝服務依賴後可使用以下指令啟動，新增的容量與等待參數會顯示於就緒回應。

```bash
python -m pip install -r requirements/requirements-service.txt
python -m src.serve_neural \
  --host 127.0.0.1 --port 8000 --torch-threads 1 \
  --max-inflight 32 --queue-timeout 1.0
```

服務啟動後可開啟 [本機 API 文件](http://127.0.0.1:8000/docs)，或使用以下指令查看設定與取得推薦。

```bash
curl http://127.0.0.1:8000/ready

curl -X POST http://127.0.0.1:8000/recommend \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"U0001","model":"v7_pytorch_two_tower","k":10,"exclude_seen":true}'
```

以下指令會啟動獨立的測試服務，完成量測後關閉該測試程序，並將結果寫入本版目錄。

```bash
python -m pytest -q
python -m src.run_neural --verify-only
python -m pip check
python -m src.benchmark_service \
  --requests 500 --concurrency 1 4 16 --repetitions 3 \
  --output reports/service_review_benchmark
```

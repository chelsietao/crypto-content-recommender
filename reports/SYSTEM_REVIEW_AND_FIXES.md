# 內容推薦系統修正與驗證報告

本次修改針對資料時間邊界、互動標籤、推薦流程與展示介面進行檢查，完成程式修正、迴歸測試與六種模型的重新評估，本文整理修改原因、處理方式與驗證結果。

本次修改日期為 2026-11-06，檢查基準為 `fb3ee2752334e1cda36a1869e1c8f706e69fead2`，相關程式、測試與產出檔案依下列項目整理。

## 1. 訓練與評估共用時間截止點

原有切分方式移除每位使用者最後一筆正向內容的配對，其他互動仍可能落在該使用者的測試時間之後，因此改用一個全域截止點，將所有訓練互動限制在截止點之前，並將內容清單限制為截止點前已發布的內容。

測試目標從截止點後的互動選取，每位使用者保留第一筆符合條件的正向內容，條件包括內容已存在於凍結清單、訓練期間未看過，以及該配對未含隱藏回饋。

驗證涵蓋訓練事件時間、測試目標時間、內容發布時間與已讀配對，對應檔案為 `src/evaluation.py` 與 `tests/test_temporal_split.py`。

## 2. 保留隱藏事件的負向標籤

互動權重包含曝光 0、點擊 1、喜歡 2、收藏 3 與隱藏 −2，針對同一位使用者與同一筆內容的事件，聚合時保留隱藏事件的負值，其餘配對採最高正向權重，讓曝光不會覆蓋隱藏標籤。

測試包含「曝光加隱藏」與「曝光、點擊再隱藏」兩種組合，兩者的聚合偏好皆為 −2，對應檔案為 `src/recommenders.py` 與 `tests/test_recommenders.py`。

## 3. 分開建立排序特徵與訓練標籤

排序器將外層訓練期間再切成歷史區段與標籤區段，使用前 70% 時間點的歷史建立興趣、熱門度、協同分數與候選集合，再以後續區段的互動建立二元標籤。

訓練範例限於歷史區段已發布、已召回且未看過的內容，同一位使用者的特徵計算一次並快取，模型訓練完成後，再以外層截止點前的歷史建立推薦時使用的特徵。

驗證會修改標籤區段的互動權重，確認訓練特徵維持相同，並檢查特徵截止點早於標籤區段開始時間，對應檔案為 `RankingRecommender` 與排序器測試。

## 4. 建立候選召回與排序邊界

熱門、內容、協同與探索四個通道各取前 20 筆未看過的內容，合併去重後形成最多 80 筆的候選集合，邏輯迴歸排序器只對集合內的內容評分，多樣性重排再處理排序結果。

評估加入 `candidate_recall` 與每位使用者的 `target_in_candidates` 欄位，記錄測試目標是否進入候選集合，測試同時檢查候選數量上限與排序輸出範圍。

## 5. 使用稀疏鄰居儲存協同相似度

使用者與內容互動改以 CSR 稀疏矩陣儲存，內容相似度採分塊計算，每筆內容只保留前 40 個正相似度鄰居並移除自身相似度，分塊大小設定為 128。

驗證涵蓋稀疏矩陣格式、每列鄰居數量上限、對角線為零與推薦分數有限值，對應檔案為 `CollaborativeFilteringRecommender` 與稀疏儲存測試。

## 6. 維持來源與主題的重排上限

多樣性重排將每個來源限制為最多 2 筆、每個主要主題限制為最多 3 筆，當候選內容無法填滿指定筆數時，回傳符合限制的內容數量。

驗證使用只有一個來源與一個主題的候選內容，請求 10 筆推薦時回傳 2 筆，並確認來源限制成立。

## 7. 保留完整的未命中紀錄

未命中分析保留全部模型與全部使用者的未命中目標，依目標是否進入候選集合分類，讓召回階段未納入與進入集合後未出現在結果清單的紀錄分開呈現。

CSV 保留完整資料，Markdown 報告依模型選取範例，測試確認各模型的未命中筆數與評估明細相符，對應輸出為 `artifacts/failure_analysis.csv` 與 `reports/FAILURE_ANALYSIS.md`。

## 8. 統一推薦介面的邊界行為

六種方法共用推薦筆數檢查，`k=0` 回傳保留欄位的空結果，負數、小數與布林值會得到明確錯誤，`exclude_seen=False` 允許已看過的內容進入候選與推薦結果。

新使用者透過既有內容與全域分數取得推薦，沒有歷史或沒有可訓練標籤時使用混合推薦，標籤只有一種類別時使用固定類別分數結合混合分數，執行摘要另記錄排序器使用的訓練模式。

空內容清單會在模型訓練前被拒絕，分數正規化會處理非有限值，對應測試位於 `tests/test_edge_cases.py`。

## 9. 將資料檢查改為執行期錯誤

資料檢查改用 `ValueError`，檢查必要欄位、識別碼、外鍵、時區時間、內容文字與品質分數，並檢查互動時間不得早於內容發布或使用者建立時間，讓檢查在 Python 最佳化模式下維持執行。

驗證包含缺漏識別碼、無限品質分數與發布前事件，對應檔案為 `validate_bundle` 與資料邊界測試。

## 10. 整理 Streamlit 展示與安裝套件

展示介面提供六種模型切換、合成使用者推薦清單、內容匹配資訊、模型指標、使用者分群表現與排序器係數，頁面顯示訓練截止時間、可用內容數與測試使用者數。

Like、Save 與 Hide 儲存於目前瀏覽器工作階段，介面移除合成內容的範例網址按鈕，並加入專案來源碼與本報告入口，應用程式啟動時在記憶體產生資料。

`requirements.txt` 保留應用程式與資料流程使用的套件，`requirements-dev.txt` 加入測試與 Notebook 工具，`.streamlit/config.toml` 設定展示主題並關閉使用統計蒐集。

## 12. 驗證項目與重跑方式

本次通過 25 項自動化測試，涵蓋資料重現性、外鍵、時間切分、未發布內容排除、隱藏標籤、候選召回、特徵時間隔離、稀疏鄰居、重排上限與介面邊界，完整資料流程已重新執行並更新產出檔案。

另以新建隔離環境安裝套件，檢查套件相依性並執行測試，Streamlit 應用程式檢查涵蓋啟動、推薦模型切換與工作階段回饋，驗證方式如下。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pip check
python -m pytest -q
python -m src.run_pipeline
streamlit run app.py
```

GitHub Actions 的驗證流程使用 Python 3.11，設定為安裝依賴、執行測試與資料流程，再保存模型指標、使用者評估明細與執行摘要。
